# Steam 状态监控插件 (astrbot_plugin_steam_monitor)

一个简单但强大的 Steam 游戏状态与成就监控插件，适用于 [AstrBot](https://github.com/AstrBotDevs/AstrBot)。

它能自动监控指定的 Steam 用户，当他们的**游戏状态**、**在线状态**、**游戏成就**或**游戏时长**发生变化时，向指定的群组或好友发送实时通知。

## ✨ 主要功能

### 自动监控与推送

- **游戏状态通知**: 有人开始玩游戏 / 退出游戏时推送。
- **上下线通知**: 有人上线 / 下线时推送（默认关闭，可开启）。
- **成就通知**: 有人解锁新成就时推送，包含成就名称和完成进度。
- **游戏时长通知**: 每个检测周期汇总游戏时长变化并推送（反隐身利器）。

### 灵活的监控组配置

通过 AstrBot WebUI 的**积木式配置界面**，无需手写 JSON，点击"添加条目"即可创建监控组：

- **多会话 x 多用户**: 每个监控组可同时绑定多个推送会话和多个 Steam 用户。
- **独立推送设置**: 每个监控组可单独覆盖全局的通知开关（状态通知、上下线、成就、游戏时长、隐私模式），也可以选择跟随全局设置。
- **备注功能**: 每个监控组可添加备注（如"宿舍群"、"同事群"），方便辨别管理。

### 隐私模式

开启后，推送消息中的 Steam 昵称会被替换为自定义代称（如"有人"或"神秘群友"），保护被监控者隐私。支持全局开启或按监控组单独设置。

### 其他特性

- **内置测试命令**: 无需真实 Steam 账号即可测试插件功能，验证配置是否生效。
- **昵称缓存**: 记录最近一次获取成功的 Steam 昵称；网络波动时优先使用缓存昵称，避免推送里出现一串数字。
- **智能缓存**: 自动缓存游戏名称（中英双语）、成就信息和玩家昵称，减少 API 请求。
- **自动重试与分批查询**: 网络失败自动退避重试，玩家信息按每批最多 100 人查询，降低被限流的风险。
- **连接池复用**: 使用持久化 HTTP 客户端，减少 SSL 握手开销。
- **并发控制**: 内置信号量限制并发请求数和请求合并机制，避免触发 API 频率限制。
- **日志脱敏**: 默认隐藏日志中的 Steam API Key 和 17 位 Steam ID，可在配置中关闭。

## ⚙️ 配置说明

安装后，在 AstrBot 管理面板 → 插件管理 → `steam_monitor` → 配置页面进行设置。

### 基础配置

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| Steam Web API 密钥 | 字符串 | 空 | **必填**，在 [Steam 开发者页面](https://steamcommunity.com/dev/apikey) 申请 |
| 敏感操作需管理员权限 | 开关 | 开 | 开启后 `steam alllist`、`steam add`、`steam remove`、`steam health` 仅管理员可用 |
| 日志脱敏 | 开关 | 开 | 开启后日志中的 Steam API Key 和 17 位 Steam ID 显示为 `***` |

### 轮询间隔

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| 在线/游戏状态检查间隔 | 整数（秒） | 180 | 每隔多久检查一次在线和游戏状态 |
| 成就状态检查间隔 | 整数（秒） | 1800 | 每隔多久检查一次成就变化，设为 `0` 关闭成就监控 |
| 请求失败最大重试次数 | 整数 | 3 | 网络请求失败时的重试上限 |

### 全局通知设置

这些是**全局总开关**，对所有监控组生效（除非监控组单独覆盖了对应设置）。

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| 状态通知 | 开关 | 开 | 总开关：游戏开始/结束 + 上下线通知 |
| 上下线通知 | 开关 | 关 | 上线/下线提醒（依赖状态通知开启） |
| 成就通知 | 开关 | 开 | 总开关：新成就通知 |
| 游戏时长通知 | 开关 | 开 | 总开关：游戏时长变化通知 |
| 隐私模式 | 开关 | 关 | 总开关：隐藏推送消息中的 Steam 昵称 |
| 隐私代称 | 字符串 | 空 | 隐私模式下替换昵称的代称，留空则默认为"有人" |

### 监控目标（核心配置）

这是插件的核心。点击"添加条目"即可创建**监控组**，每个监控组包含：

#### 1. 备注

可选填，仅用于辨别不同监控组（如"宿舍群"、"工作群"），不影响功能。

#### 2. 推送会话列表

填写需要接收推送的**会话 ID**（UMO 格式）。每个监控组可绑定多个会话。

> 💡 **如何获取会话 ID？** 在需要推送的群聊或私聊中发送 `sid` 命令，机器人会回复当前会话的完整 ID。

会话 ID 格式示例：
- QQ 群聊：`napcat:GroupMessage:987654321`
- QQ 私聊：`napcat:FriendMessage:123456`

#### 3. Steam ID 列表

填写要监控的 17 位 Steam 数字 ID。每个监控组可监控多个用户。

首次保存配置并成功获取昵称后，插件会自动把昵称写进 ID 后面的中文括号中，例如 `76561198xxxxxxxxx（张三）`。之后可以手动修改括号内的文字；同一个 Steam ID 出现在多个监控组时，保存后备注会同步到所有位置。

想重新自动获取昵称，改成 `76561198xxxxxxxxx（）`；想关闭这个用户的备注，只保留纯 ID。昵称中如果本身包含中文括号，插件会自动换成半角括号，避免配置无法解析。插件实际监控时只使用括号前的纯 ID，备注不影响功能。

> 💡 **如何查找 Steam ID？** 打开 Steam 客户端 → 个人资料页 → URL 栏中的 17 位数字。或使用 [SteamID Finder](https://www.steamidfinder.com/) 查询。

#### 4. 推送设置（可选覆盖）

每个通知项都是一个三态下拉框：`跟随全局`、`开启`、`关闭`。默认全部跟随全局；需要为某个监控组单独设置时，直接把对应项改成 `开启` 或 `关闭` 即可。

可覆盖的设置项：
- **状态通知**: 是否推送游戏开始/结束
- **上下线通知**: 是否推送上线/下线
- **成就通知**: 是否推送新成就
- **游戏时长通知**: 是否推送游戏时长变化
- **隐私模式**: 是否隐藏 Steam 昵称

### 配置示例

假设你需要：
- 在"宿舍群"中监控 3 个好友，开启所有通知（跟随全局）
- 在"工作群"中只监控 1 个好友，仅开启成就通知，关闭其他

只需添加两个监控组：

**监控组 1**（备注：宿舍群）
- 会话列表：`napcat:GroupMessage:111111111`
- Steam ID 列表：`76561198xxxxxxxxx`、`76561198yyyyyyyyy`、`76561198zzzzzzzzz`
- 推送设置：全部选择"跟随全局"

**监控组 2**（备注：工作群）
- 会话列表：`napcat:GroupMessage:222222222`
- Steam ID 列表：`76561198aaaaaaaaa`
- 推送设置：
  - 状态通知：关闭
  - 成就通知：开启
  - 游戏时长通知：关闭

## 📝 命令列表

> `<steam_id>` 代表 17 位纯数字 Steam ID。标记为"管理员"的命令受 `敏感操作需管理员权限` 配置项控制。

### 查询指令

| 命令 | 权限 | 说明 |
|------|------|------|
| `steam list` | 所有人 | 查看**当前会话**监控的所有玩家的实时状态 |
| `steam alllist` | 管理员 | 查看**所有监控组**的所有玩家状态，按组分类显示 |
| `steam health` | 管理员 | 查看 API 状态、任务运行情况、昵称缓存和配置规模 |

### 管理指令

| 命令 | 权限 | 说明 |
|------|------|------|
| `steam add <steam_id>` | 管理员 | 将一个 Steam 用户添加到当前会话的监控组中 |
| `steam remove <steam_id>` | 管理员 | 将一个 Steam 用户从当前会话的监控组中移除 |

> 💡 如果当前会话尚未关联任何监控组，使用 `steam add` 会自动创建一个新的监控组并绑定当前会话。

### 测试指令

这些指令会为当前会话创建一个虚拟的"测试用户"，并模拟一次状态/成就变更。用于验证插件是否正常工作，无需真实 Steam 账号，也不会写入 WebUI 配置。

| 命令 | 模拟场景 | 预期推送 |
|------|----------|----------|
| `steam test status` | 测试用户退出游戏（游戏中 → 在线） | "测试ID 退出了游戏 Cyberpunk 2077" |
| `steam test offline` | 测试用户下线（游戏中 → 离线） | "测试ID 下线了"或"测试ID 退出了游戏 Cyberpunk 2077"（取决于配置） |
| `steam test achievements` | 测试用户解锁一个 Cyberpunk 2077 成就 | 成就通知，含成就名和完成进度 |

> 测试完成后，测试用户的状态和临时监控会在一个检测周期后自动恢复并移除。

## ❓ 常见问题

**Q: 插件启动后没有任何推送？**

A: 插件首次启动时会记录当前状态作为基准，不会推送。请等待至少一个检测周期（默认 3 分钟）后，被监控用户发生状态变化才会触发推送。你也可以使用 `steam test status` 等测试命令验证。

**Q: Steam ID 怎么查？**

A: 打开 Steam 客户端 → 个人资料页 → URL 栏中的 17 位数字。或使用 [SteamID Finder](https://www.steamidfinder.com/)。

**Q: 会话 ID 怎么查？**

A: 在需要推送的群聊/私聊中发送 `sid` 命令，机器人会回复完整的会话 ID。

**Q: 为什么消息里显示"昵称未知"？**

A: 这表示插件还没有成功获取过该用户的 Steam 昵称。请先运行 `steam health` 检查 API Key 和网络状态；之后任意一次成功获取都会写入昵称缓存，网络波动时会优先使用缓存昵称。

**Q: 可以同一个 Steam 用户被多个监控组监控吗？**

A: 可以。同一个 Steam ID 可以出现在不同监控组中，每个监控组会根据各自的推送设置独立推送。

**Q: 修改配置后需要重启吗？**

A: 在 WebUI 中修改并保存插件配置后，AstrBot 会自动热重载插件，无需手动重启机器人。如果是手动修改插件代码或数据文件，再使用插件管理页面的重载功能。

### 命令与多监控组的交互行为

以下用具体场景说明命令在涉及多个监控组时的行为：

**场景 1：一个监控组绑定了多个会话，在其中一个群里使用 `steam add`/`steam remove`**

> 假设"监控组 A"同时绑定了 QQ 群 111 和 QQ 群 222。你在群 111 中执行 `steam add 76561198xxxxxxxxx`。

- 插件会找到包含群 111 的监控组（即监控组 A），将该 Steam ID 添加进去。
- 由于群 222 也在同一个监控组中，**群 222 也会同步监控这个新添加的用户**。
- `steam remove` 同理：在群 111 中移除，群 222 也不再监控该用户。
- **总结**：`steam add`/`steam remove` 操作的是监控组，不是单个会话。同组内的所有会话共享监控列表。

**场景 2：同一个会话出现在多个监控组中，使用 `steam list`**

> 假设群 111 同时出现在"监控组 A"（监控张三、李四）和"监控组 B"（监控王五）中。你在群 111 中执行 `steam list`。

- 插件会找到所有包含群 111 的监控组，**汇总去重**后列出所有关联的 Steam 用户。
- 因此你会看到张三、李四、王五三个人的状态，不会重复显示。

**场景 3：同一个会话出现在多个监控组中，使用 `steam add`**

> 同上配置，你在群 111 中执行 `steam add 76561198zzzzzzzzz`。

- 插件会找到包含群 111 的所有监控组，但只将新 ID 添加到**第一个匹配的监控组**（即监控组 A）。
- 如果你希望添加到监控组 B，需要在 WebUI 中手动操作。
- `steam remove` 同理：只从第一个找到该 ID 的监控组中移除。

**场景 4：同一个 Steam 用户在多个监控组中，自动推送会重复吗？**

> 假设张三同时出现在"监控组 A"（绑定群 111）和"监控组 B"（也绑定群 111，但关闭了成就通知）中。

- 张三开始玩游戏时，群 111 会收到**两条**状态通知（每个监控组独立推送一次）。
- 张三获得新成就时，群 111 只会收到**一条**成就通知（来自监控组 A），因为监控组 B 关闭了成就通知。
- **建议**：除非有意为不同推送设置做区分，否则避免将同一个会话放入多个监控组，以免收到重复推送。

### 管理指令

- **`steam add <steam_id>`** `(管理员)`
  - **功能**: 在**当前会话**的监控列表中添加一个 Steam 用户。
  - **示例**: `steam add 76561198872155923`
  - **权限**: 管理员

- **`steam remove <steam_id>`** `(管理员)`
  - **功能**: 从**当前会话**的监控列表中移除一个 Steam 用户。
  - **示例**: `steam remove 76561198872155923`
  - **权限**: 管理员

### 测试指令

这些指令会自动将一个虚拟的“测试用户”加入当前会话的监控列表，并模拟一次状态变更。你可以用它们来检查插件是否配置正确、通知是否能正常发出。

- **`steam test status`**
  - **功能**: 模拟一次“测试用户”**退出游戏**（从“游戏中”变为“在线”）的状态变更。
  - **预期结果**: 在下一个状态检查周期，机器人会发出一条“退出了游戏”的通知。

- **`steam test offline`**
  - **功能**: 模拟一次“测试用户”**从游戏中直接下线**的状态变更。
  - **预期结果**: 在下一个状态检查周期，机器人会根据你的会话配置，发出“下线了”或“退出了游戏”的通知。

- **`steam test achievements`**
  - **功能**: 模拟一次“测试用户”在《赛博朋克 2077》中获得一个**新成就**。
  - **预期结果**: 在下一个成就检查周期，机器人会发出一条获得新成就的通知。如果测试用户已“全成就”，会自动重置其成就列表以便再次测试。
